# 通用方案设计文档生成器

根据中国联通概要设计说明书模板标准，生成结构化的方案设计文档。

## When to Use

- 用户要求生成「概要设计说明书 / 方案设计说明书 / 方案设计文档 / 技术设计文档」
- 用户需要将写好的 Markdown 方案文档（含 Mermaid 图表）转换为符合中国联通模板样式的 `.docx`
- 触发词：概要设计、方案设计、方案设计说明书、生成 docx、markdown 转 word、Mermaid 转图进 Word
- 需要把 Mermaid 流程图/时序图等渲染为 PNG 并嵌入 Word（支持离线 `--mode local`）

## 文档模板

生成的文档必须严格包含以下章节结构，不得遗漏。各章节的详细内容根据用户提供的具体需求填充。

### 文档头部信息

## 生成规则

1. **必填章节**：所有10个章节必须生成，即使内容为"无"或"不涉及"也要保留章节结构
2. **占位符替换**：所有 `{xxx}` 占位符必须替换为实际内容，不得保留花括号占位符
3. **功能点类型**：使用标准编码（ST21.业务服务、ST31.文件接口、ST32.实时接口、ST33.异步接口、ST34.消息队列、ST51.数据标签、ST55.数据加工、ST56.基础数据模型、ST61.性能优化、ST62.安全合规、ST63.高可用设计）
4. **操作类型**：仅使用 新增/修改/删除
5. **复杂度**：仅使用 简单/一般/复杂
6. **表格格式**：所有表格使用 Markdown 标准格式，列对齐
7. **版本号**：初始版本为 v1.0，后续修订递增
8. **文档语言**：中文

## 环境依赖与安装

本 skill 依赖以下 Python 库，使用前需安装：

| 依赖 | 用途 | 备注 |
|------|------|------|
| python-docx | Markdown → .docx 转换（md2docx.py） | 必须 |
| mermaid-py | Mermaid 代码块 → PNG 渲染（render_mermaid.py，在线模式） | 必须 |
| playwright | Mermaid 本地离线渲染后端（render_mermaid.py `--mode local`） | 可选，仅离线/内网/敏感场景需要 |

### 安装命令

在项目根目录（含 `.trae` 的目录）执行：

```bash
pip install -r .trae/skills/markdownToWord/requirements.txt

# 仅当需要本地离线渲染时，额外安装：
pip install playwright
playwright install chromium
```

### Mermaid 渲染的两种模式（重要）

`render_mermaid.py` 支持两种渲染模式，通过 `--mode` 参数切换：

| 模式 | 命令参数 | 依赖 | 网络 | 适用场景 |
|------|---------|------|------|---------|
| 在线（默认） | `--mode online`（或不传） | mermaid-py | 需联网 | 一般场景，快速出图 |
| 本地离线 | `--mode local` | playwright + chromium | 首次需联网拉取 mermaid.min.js，之后完全离线 | 离线/内网环境、敏感业务（内容不外传） |

- **在线模式**：`mermaid-py` 默认调用 [mermaid.ink](https://mermaid.ink) 在线服务，**需要联网**，且图表文本会上传至第三方服务。
- **本地离线模式**：通过 Playwright 驱动本地 Chromium 渲染，图表内容不出本机。
  - 首次使用会自动从 CDN 拉取 `mermaid.min.js` 并缓存到 `skills/markdownToWord/assets/mermaid.min.js`，**之后完全离线可用**；
  - 内网环境可手动下载 [mermaid.min.js](https://cdn.jsdelivr.net/npm/mermaid@10/dist/mermaid.min.js) 放入上述 `assets/` 目录，或通过环境变量 `MERMAID_JS_PATH` 指向本地文件；
  - 脚本内置 `mermaid.parse()` 预检，语法错误的图表会明确报失败（不会把"错误炸弹"图当成功写进文档）。

```bash
# 本地离线渲染示例
python .trae/skills/markdownToWord/render_mermaid.py <input.md> <output_dir> -p "diagram" --mode local
```

> ⚠️ 涉及敏感业务的概要设计文档，建议优先使用 `--mode local` 本地渲染（内容不外传）。

## 使用方式
当用户要求生成方案设计文档时，按以下步骤执行：
1.  收集需求信息：需求编号、需求名称、能力集名称、项目名称
2.  分析需求内容，提取功能模块、数据结构、接口、性能、安全等设计要素
3.  按照模板逐章节生成文档内容（Markdown格式），**并在需要图表的地方插入 Mermaid 代码块**（例如：` ```mermaid graph TD... ``` `）
4.  将所有 `{xxx}` 占位符替换为实际内容
5.  将 Markdown 内容写入临时文件 `.trae/tmp/solution_design_tmp.md`（项目根目录相对路径，Windows 下勿用 `/tmp`）
6.  **渲染 Mermaid 图表为 PNG**（若文档不含 Mermaid 代码块，可跳过本步与第 7 步）
    ```bash
    python .trae/skills/markdownToWord/render_mermaid.py .trae/tmp/solution_design_tmp.md .trae/tmp/diagrams -p "diagram"
    # 离线/内网/敏感业务：追加 --mode local（需已安装 playwright + chromium，见「环境依赖与安装」）
    ```
    - 脚本输出 `完成：成功 N，失败 M`；任意一块渲染失败即返回退出码 `1`。
    - **渲染失败分支（见下方「渲染失败处理」）**：出现失败时**不要**继续第 7 步替换，避免写入不存在的图片路径。

7.  **（仅当渲染全部成功时）将 Mermaid 代码块替换为图片链接**
    - 将 ` ```mermaid ... ``` ` 按出现顺序逐一替换为 `![图表描述](.trae/tmp/diagrams/diagram_1.png)`、`diagram_2.png`……
    - 序号必须与第 6 步生成的 `diagram_{i}.png` 严格对应（从 1 开始）。
    - 若第 6 步失败，则**跳过本步**，直接保留 Mermaid 代码块进入第 8 步。

8.  调用转换脚本生成 Word 文档：
    ```bash
    python .trae/skills/markdownToWord/md2docx.py .trae/tmp/solution_design_tmp.md -o "方案/CUSRI-SDS-{需求编码}-{需求名称}-方案设计说明书.docx"
    ```
9.  删除临时目录 `.trae/tmp/`
10. 输出文件路径告知用户

### 渲染失败处理（Mermaid 转图失败时）

当第 6 步出现 `失败 M > 0`（常见原因：离线 / 内网导致 mermaid.ink 在线服务不可达，或未配置本地浏览器后端），按以下分支处理：

1. **禁止写入坏链**：**不要**将不存在的 `diagram_N.png` 路径写入 Markdown —— 否则 `md2docx.py` 会把图片段落降级为字面文本，文档出现损坏链接。
2. **保留 Mermaid 代码块原样**：直接跳过第 7 步、执行第 8 步。`md2docx.py` 会将 ` ```mermaid ... ``` ` 作为等宽代码块渲染，文档可正常打开，仅架构图以代码形式呈现。
3. **修复后重试（可选）**：
   - 在线渲染失败 → 检查网络连通性；或改用本地离线模式：安装 `pip install playwright && playwright install chromium` 后，在渲染命令追加 `--mode local`。
   - 本地后端仍失败 → 查看脚本 stderr 的 `FAIL: ...` 具体错误（语法错误会以 `Mermaid 语法/解析错误：` 开头），修复 Mermaid 代码后重跑第 6 步；渲染成功后再补做第 7、8 步。
4. **告知用户**：本次文档已生成，但 Mermaid 图表**未转为图片**（以代码块呈现）；如需正式配图，请按上述步骤修复环境后重跑渲染与转换。

### 输出规则

- **输出格式**：直接生成 `.docx` Word 文档，不保留 `.md` 中间文件
- **输出目录**：`方案/` 目录

### 转换实现方式

使用 python-docx 库进行 Markdown 到 Word 的转换，核心实现要点：

1. **页面设置**：设置 `section.page_width`, `section.page_height`, `section.top_margin` 等（A4 纵向，上下 2.54cm，左右 3.17cm）
2. **无页眉页脚**：不设置 `section.header` / `section.footer` 内容，文档全局无页眉、无页脚、无页码
3. **标题样式**：使用 `document.styles['Heading 1']` 等并设置中文字体（统一宋体）、数字英文字体（Times New Roman）、对应字号
4. **表格**：使用 `document.add_table(rows, cols, style='Table Grid')`
5. **字体设置**：中文字体通过 `rFonts.set(qn('w:eastAsia'), ...)`，数字英文字体通过 `font.name = 'Times New Roman'`

## Common Mistakes

- ❌ 渲染失败仍把 `diagram_N.png` 写入 Markdown → ✅ 失败时保留 Mermaid 代码块原样（见「渲染失败处理」），不写坏链，否则 `md2docx.py` 会降级为字面文本
- ❌ 未装 `python-docx` 直接跑 `md2docx.py` → ✅ 先 `pip install -r requirements.txt`
- ❌ 内网 / 敏感业务用在线模式（内容上传统三方 mermaid.ink） → ✅ 用 `--mode local` 本地渲染，内容不出本机
- ❌ 保留 `{xxx}` 花括号占位符 → ✅ 所有占位符必须替换为实际内容，不得遗留
- ❌ 多图时序号与渲染输出不对应 → ✅ 替换顺序严格按 `diagram_1.png`、`diagram_2.png`… 与渲染产物一一对应
