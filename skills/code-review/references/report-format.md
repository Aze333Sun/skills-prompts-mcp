# Review 报告输出格式

用户需要在 10 秒内抓住关键问题。**简洁是第一优先级。**

## 报告模板

```markdown
## Code Review 报告

**X 个文件 | +Y/-Z 行 | 深度审查 | 风险：高**

> P0/P1/P2/P3 问题不阻塞 iCode 合入, 建议修复；阻塞类问题必须修复，会影响 iCode 合入，必须修复。
> 降级/分批/局部审查等特殊说明（无则省略）

---

### 🔴🔴 阻塞合入问题 (N)

**1. [file.ts:42](file.ts#L42)** — 一句话描述风险和触发条件 [locked]
建议：一句话修复方向

### 🔴 P0 严重 (N)

**2. [file.ts:80](file.ts#L80)** — 一句话描述风险和触发条件
建议：一句话修复方向

### 🟠 P1 高优 (N)

**3. [file.ts:100](file.ts#L100)** — 一句话描述
建议：一句话建议

### 🟡 P2 中等 (N)

### 🔵 P3 低优 (N)

---

**结论**：{动态生成，见下方规则}
```

## 结论生成规则

- **存在阻塞合入问题**：输出 `存在**阻塞合入**问题，建议立即修复`
- **不存在阻塞合入问题，但存在 P0/P1 问题**：输出 `无阻塞合入问题，P0/P1/P2/P3 问题不阻塞 iCode 合入，建议修复`
- **仅存在 P2/P3 问题**：输出 `无阻塞合入问题，P2/P3 建议后续优化，可直接合入`
- **无问题**：输出 `审查通过，可直接合入`

## 输出规则

1. 每条 finding **限 2 行**：问题描述 + 建议，各 1 句话
2. 空级别直接省略，无问题写"审查通过"
3. 使用可点击路径 `[src/file.ts:42](src/file.ts#L42)`
4. 超过 10 条时：展示阻塞合入问题/P0/P1 全部 + P2/P3 各最多 3 条，末尾注明"另有 N 条，回复「展开」可查看"
5. 来源维度不展示，用户追问时再补充
6. **Critical finding 标记规则**：每条 Critical finding 末尾必须保留 `[locked]` 标记，且在 finding 标题旁额外注明 `阻塞合入`，让用户一眼可识别
