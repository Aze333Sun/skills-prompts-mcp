# AI / LLM 开发提示词

## 1. Prompt 工程优化

```
请帮我优化以下 Prompt，提升 AI 输出质量和一致性：

原始 Prompt：
```
{粘贴 Prompt}
```

目标模型：{Claude / GPT / Gemini}
任务类型：{生成 / 摘要 / 分类 / 推理 / 代码}

请从以下维度优化：
1. **清晰性**：任务描述是否无歧义？角色是否明确？
2. **结构**：是否用分隔符清晰划分指令/上下文/输入/输出格式？
3. **约束**：关键约束是否显式声明（不要/必须/优先）？
4. **示例**：是否需要 Few-shot 示例？示例是否覆盖边界情况？
5. **输出格式**：是否指定了精确的输出格式（JSON Schema / Markdown）？
6. **思维链**：复杂推理任务是否需要引导思考步骤？

输出优化后的 Prompt + 每项改动的理由。
```

## 2. Function Calling / Tool Use 设计

```
请为以下业务场景设计 AI Agent 的 Tool/Function 定义：

业务场景：{描述：如 AI 客服助手，需要查询订单、退款、转人工}

输出每个 Tool 的：
1. 函数名（语义化、小写+下划线）
2. 函数描述（一句话，让模型准确判断何时调用）
3. 参数定义（JSON Schema，包含类型、描述、是否必填、枚举值）
4. 调用示例（实际 JSON）
5. 返回格式（JSON Schema + 示例）
6. 权限要求（哪些 Tool 需要用户确认后执行）

遵循 OpenAI Function Calling / Anthropic Tool Use 标准格式。
输出可用的 JSON 定义。
```

## 3. RAG 系统调优

```
请帮我诊断和优化 RAG 系统的效果问题：

系统架构：{Embedding 模型 / 向量库 / LLM / Chunk 策略}
数据集特点：{文档类型、平均长度、语言}
当前问题：{检索不准 / 答案幻觉 / 遗漏关键信息 / 响应太慢}

请从以下维度诊断：
1. Chunk 策略（大小是否合适？是否保留了上下文重叠？）
2. Embedding 模型选择（对当前语言的支持如何？）
3. 检索策略（Top-K 是否合理？是否需要重排序？）
4. Prompt Template（上下文是否充分利用？是否有引用要求？）
5. 检索质量评估（是否做了命中率测试？）
6. 混合检索（关键词 + 语义是否需要结合？）

每项给出具体优化参数和预期效果。
```

## 4. LLM 应用架构设计

```
请帮我设计一个 LLM 应用的完整架构：

应用类型：{聊天机器人 / Agent / 内容生成 / 数据分析 / RAG 问答}
预期用户量：{DAU}
延迟要求：{P99 < X ms}

请输出：
1. 整体架构图（文字描述各组件及交互）
2. 模型选型（基础模型、微调 vs 提示词、是否自部署）
3. Prompt 管理策略（版本控制、A/B 测试、模板化）
4. 记忆机制（短期/长期记忆、摘要策略、上下文窗口管理）
5. 安全护栏（输入过滤、输出审核、敏感词、越狱防护）
6. 可观测性（Token 用量、延迟、成功率、成本监控）
7. 降级策略（模型不可用时的 fallback）
8. 成本估算（每千次对话的预估成本）
```

## 5. LLM 输出质量评估

```
请帮我建立一套 LLM 输出质量评估体系：

任务类型：{文本生成 / 代码生成 / 问答 / 摘要}
评估目标：{正确性 / 相关性 / 一致性 / 安全性}

请设计：
1. 自动化评估指标（如 ROUGE、BERTScore、自定义规则）
2. 人工评估标准（评分 1-5 的 Rubric）
3. LLM-as-Judge 的 Prompt（让另一个 LLM 评估输出质量）
4. 评估数据集构建策略（如何选择代表性样本）
5. 回归测试机制（每次 Prompt 改动后跑 Eval）
6. Bad Case 分析流程（错误分类→根因→修复→验证）

输出完整评估脚本框架和 Judge Prompt。
```

## 6. Token 优化

```
请分析以下 AI 交互的 Token 消耗并给出优化方案：

使用场景：{如：Claude Code 中的 SKILL.md / 系统 Prompt / 长对话}
当前 Token 分布：
- 系统提示词：~{N} tokens
- 工具定义：~{N} tokens
- 历史对话：~{N} tokens
- 每次用户输入：~{N} tokens

优化策略：
1. 系统提示词如何精简（去掉冗余词、合并相似指令）
2. 工具定义描述是否可压缩（保留区分度信息）
3. 对话历史压缩策略（滑动窗口 vs 摘要 vs 关键帧提取）
4. 渐进式加载（progressive disclosure）设计
5. 哪些信息可以从上下文窗口移到外部工具

输出优化后各部分的 Token 占用估算，目标节省 50%。
```

## 7. AI Agent 行为设计

```
请帮我设计一个 AI Agent 的行为模式：

Agent 角色：{如：高级软件工程师 / 数据分析师 / 客服}
工作方式：{独立完成任务 / 与人协作}
可用的工具：{列出 Agent 可以调用的工具}

请设计：
1. Agent 人格（简短的系统 Prompt）
2. 行为准则（永远做什么 / 绝不做什么）
3. 工具选择决策树（什么情况下用哪个工具）

5. 与人交互的边界（什么情况下必须询问用户）
6. 输出的自我检查清单（Agent 完成任务后的自查项）
```

## 9. LLM 安全防护

```
请为我的 LLM 应用设计安全防护方案：

应用描述：{面向什么用户、处理什么数据、有什么外部接口}
使用的模型：{Claude / GPT / 开源模型}
当前担忧：{Prompt 注入 / 越狱 / 数据泄露 / 滥用}

请设计分层防护：
1. **输入层**：敏感词过滤、注入检测、速率限制
2. **Prompt 层**：系统 Prompt 中的安全指令、角色约束
3. **输出层**：内容审核、敏感信息脱敏、格式校验
4. **工具层**：高风险操作的人机确认、权限最小化
5. **监控层**：异常行为告警、审计日志

每层给出具体的防护措施和实现示例。
```
