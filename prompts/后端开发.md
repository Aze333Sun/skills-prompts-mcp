# 后端开发提示词

## 1. RESTful API 设计

```
你是一位资深后端架构师。请为以下业务场景设计一套 RESTful API：

业务需求：{描述业务场景}

输出：
1. 资源 URL 结构（遵循 REST 规范，用名词复数）
2. 每个端点的 HTTP Method、路径、请求/响应体示例（JSON）
3. 分页、排序、筛选的 Query 参数设计
4. 错误码体系（HTTP 状态码 + 业务错误码）
5. 幂等性设计（哪些端点需要幂等键）
6. API 版本策略（URL 路径 / Header / Query）

使用 OpenAPI 3.1 规范描述，确保 URL 命名一致、语义清晰。
```

## 2. 数据库表设计

```

业务场景：{描述业务，如：一个多租户的工单系统}

## 3. 接口安全加固

```
请审查以下 API 的安全问题，并给出加固方案：

```{语言}
{粘贴 API 代码}
```

重点检查：
1. 认证鉴权是否完善（JWT 过期、刷新机制）
2. SQL 注入风险（参数化查询）
3. 越权风险（横向/纵向权限校验）
4. 敏感数据是否脱敏（日志、响应体）
5. 速率限制是否到位
6. 输入校验是否严格
7. CORS 配置是否安全

输出分级风险报告 + 修复代码。
```

## 9. 认证授权系统

```

- 支持邮箱密码 + 手机验证码 + OAuth2.0（Google/GitHub/微信）多种登录

- RBAC 权限模型（用户 → 角色 → 权限）
- 支持多租户/工作区隔离
- 会话管理（单设备登录/多设备登录/强制下线）

输出：
1. 数据库表设计
2. 登录/注册/刷新令牌 完整流程（时序图文字描述）
3. 权限校验中间件设计
4. Token 安全存储建议（httpOnly cookie / Authorization header）
5. 核心代码示例
```
